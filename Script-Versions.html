Site Access Requests - What Each Version Does

Each version does everything the previous one did, plus the items listed under it.

Version A (Day 1)

  • Checks the Site Access Requests list every 30 seconds.
  • Makes the security group a site collection admin of the requested site once the request's start date arrives.
  • Takes that access away when the requester asks for removal, or when the removal date arrives.
  • Updates the request with its new status and the date access was added or removed.
  • Leaves "Modified" and "Modified By" showing the last person who edited the request.
  • If something goes wrong, the reason appears in the request's "Last Result" column.

Version B (Day 2)

  • Only gives access to sites listed in the Teams Attestation Tracker.
  • Accepts a site address copied from any page of the site, with or without a trailing slash, in any letter case.
  • Gives clear messages, for example when a site is not in the tracker or no longer exists.
  • Keeps a short history of everything done to each request.
  • Once access is removed, moves the request to the Site Access Requests Archive list, keeping who created and last changed it, and when.
  • Keeps a daily activity log on the server running it.

Version C (Day 3)

  • When a request fails, waits longer between each new attempt instead of retrying every 30 seconds.
  • When someone fixes a failed request, tries again straight away.
  • Keeps the security group's access to a site while another open request for that site still needs it.
  • Double-checks the archived copy before removing the original request.
  • Recovers by itself after a temporary connection problem.

Final Version

  • Can run on two or three servers at the same time for reliability, without two servers handling the same request.
  • If one server stops partway through a request, another server picks it up after a few minutes.
